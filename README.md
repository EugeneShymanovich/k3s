# k3s on Hetzner Cloud — Terraform + Ansible

Opinionated, disposable k3s cluster on Hetzner Cloud. **Terraform** provisions
the infrastructure (network, firewall, SSH key, nodes), **Ansible** configures
the OS and installs/joins k3s. One `terraform apply` plus one
`ansible-playbook` gives you a working cluster and a local kubeconfig.

Designed for learning and short-lived test clusters: bring it up, use it,
`terraform destroy` it.

---

## Architecture

```
                         Internet
                             │
                22, 6443 open only to the operator IP
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
   ┌────▼─────┐         ┌────▼─────┐         ┌────▼─────┐
   │ k3s-cp1  │         │  k3s-w1  │         │  k3s-w2  │
   │ control  │         │  agent   │         │  agent   │
   │ plane    │         │          │         │          │
   └────┬─────┘         └────┬─────┘         └────┬─────┘
        │ 10.0.0.11          │ 10.0.0.21          │ 10.0.0.22
        └───────────┬────────┴────────┬───────────┘
                    │  private network 10.0.0.0/24
                    │  (all TCP/UDP/ICMP allowed inside)
```

- **k3s-cp1** — control plane, private IP `10.0.0.11`.
- **k3s-w1 / k3s-w2** — agents, `10.0.0.21` / `10.0.0.22`.
- Defaults: location `hel1`, server type `cx23` (2 vCPU / 4 GB / 40 GB),
  image `ubuntu-26.04`.
- Firewall: inbound `22` and `6443` **only from your current public IP**;
  full traffic from `10.0.0.0/24`; `6443` is never exposed to `0.0.0.0/0`.

## Security model

- The Hetzner API token lives **only** in `terraform.tfvars`, which is
  `.gitignore`d. Never paste it into issues, chat, or commits.
- `terraform.tfstate` (and backups) contain infrastructure metadata and are
  **not** committed. Keep them safe: without state, Terraform cannot destroy.
- The Ansible inventory (real public/private IPs) is generated at apply time and
  is `.gitignore`d.
- The k3s node token (`/var/lib/rancher/k3s/server/node-token`) is read at
  runtime with `no_log: true` and never written to disk by Ansible.
- The SSH private key never leaves your workstation.
- Rotate the k3s token if it leaks (see below).

## Quick start

### 1. Configure the Hetzner token

```bash
cp terraform.tfvars.example terraform.tfvars
# edit terraform.tfvars: hcloud_token = "<your token>"
```

Optional overrides (all have defaults) — see `variables.tf`:

```hcl
location            = "hel1"
server_type         = "cx23"
image               = "ubuntu-26.04"
ssh_public_key_path = "~/.ssh/id_ed25519.pub"
# ssh_cidr          = "203.0.113.10/32"   # otherwise auto-detected
```

### 2. Provision the infrastructure

```bash
terraform init
terraform plan
terraform apply        # type: yes
terraform output
```

This creates the network, firewall, SSH key and the three nodes, and writes
`ansible/inventory/hosts.ini` from the real IPs. Verify it:

```bash
cat ansible/inventory/hosts.ini
```

### 3. Configure the cluster

```bash
cd ansible
ansible all -m ping            # connectivity check
ansible-playbook site.yml
```

The playbook performs, in order:
1. **common** — `apt update` + safe upgrade, NTP enabled, base packages,
   detects the private interface that holds the node's private IP.
2. **k3s_server** — installs the control plane with
   `--node-ip`, `--flannel-iface`, `--tls-san=<public IP>`, waits for `Ready`,
   reads the node token (in memory only).
3. **k3s_agent** — installs each agent with `K3S_URL=https://<cp1 private>:6443`
   and the token taken from the control plane's `hostvars`.
4. **kubeconfig** — fetches `/etc/rancher/k3s/k3s.yaml` to
   `~/.kube/k3s-test.yaml` and rewrites `127.0.0.1` to the public IP of cp1.
5. **verify** — prints `k3s kubectl get nodes -o wide`.

### 4. Use the cluster

```bash
export KUBECONFIG=~/.kube/k3s-test.yaml
kubectl get nodes -o wide
kubectl get pods -A
```

`KUBECONFIG` works because port `6443` is open to your IP and the API
certificate was issued with `--tls-san=<public IP of cp1>`.

## Day-2 operations

**Re-run configuration** (idempotent; skips install if k3s already present):

```bash
cd ansible && ansible-playbook site.yml
```

**Add a worker:** add an entry to `locals.nodes` in `main.tf`, then:

```bash
terraform apply
cd ansible && ansible-playbook site.yml   # creates + joins the new node
```

**Migrate to a new public IP of your workstation:** just re-run
`terraform apply`; the firewall rule is refreshed from the auto-detected IP
(or set `ssh_cidr` explicitly).

**Destroy everything:**

```bash
cd /path/to/k3s
terraform destroy
rm -f ~/.kube/k3s-test.yaml ansible/inventory/hosts.ini
```

**Rotate the k3s token** (do it before agents join, or re-join them after):

```bash
sudo systemctl stop k3s
sudo rm /var/lib/rancher/k3s/server/token
sudo systemctl start k3s
sudo cat /var/lib/rancher/k3s/server/node-token   # keep private
```

## How it works

### Terraform

- `data.http.my_ip` + `locals.ssh_cidr` detect the operator IP for the
  firewall rules when `ssh_cidr` is not set.
- `hcloud_firewall.cluster` allows `tcp/22` and `tcp/6443` from `ssh_cidr`,
  and all `tcp`/`udp`/`icmp` from `10.0.0.0/24`.
- `hcloud_server.node` is a `for_each` over `locals.nodes`; each node gets a
  static private IP and the firewall, and is labeled
  `role=control-plane|worker`.
- `local_file.ansible_inventory` renders `templates/inventory.tpl` into
  `ansible/inventory/hosts.ini`, grouped into `control_plane` and `workers`.

### Ansible

- Roles are idempotent: install steps are guarded by
  `stat /usr/local/bin/k3s`.
- The private interface is discovered dynamically from the private IP, so it
  does not matter whether it is `enp7s0` or `ens10`.
- The agent role reads `k3s_node_token` from the control plane's hostvars, so no
  token is stored anywhere.
- `no_log: true` protects the token in task output.

## Troubleshooting

| Symptom | Check |
|---------|-------|
| `ansible all -m ping` fails | `ansible/inventory/hosts.ini` exists and has correct IPs; your IP is allowed by the firewall |
| Agent missing in `get nodes` | On the node: `systemctl status k3s-agent`, `journalctl -u k3s-agent -n 100` |
| Node `NotReady` | `kubectl describe node <name>`; Flannel/CNI; time sync (`timedatectl`) |
| Local `kubectl` TLS/timeout | kubeconfig points at the public IP; port `6443` open for your IP; `--tls-san` correct |
| Pods on different nodes cannot talk | `--flannel-iface` correct; firewall allows `10.0.0.0/24` |
| `terraform apply` auth error | token is 64 chars, same project, Read & Write |
| Inventory stale after destroy | re-run `terraform apply`, or delete `ansible/inventory/hosts.ini` |

Useful commands:

```bash
sudo k3s kubectl get events -A --sort-by=.lastTimestamp
sudo journalctl -u k3s -n 100 --no-pager
sudo journalctl -u k3s-agent -n 100 --no-pager
terraform state list
```

## Limitations

- Single control plane (no HA). Fine for learning/test; not production.
- k3s uses its bundled Traefik; the Hetzner Cloud Controller Manager is not
  enabled (no Hetzner LoadBalancer integration).
- Local state only (no remote backend). Do not lose `terraform.tfstate`.
